垃圾收集器

共有7种垃圾收集器

  1. 从回收对象上看分成新生代，老年代以及混合3种
  2. 从多线程角度看，有多线程的也有单线程的
  3. 从与工作线程的串行与并行角度看，有串行的也有并行的，其中只有CMS与G1是并行的，其他都是串行的

我分成4组介绍一下吧

  1. 第一组：Serial 收集器与Serial Old 收集器

    都是单线程的，分别是新生代和老年代的垃圾收集器；

    其中新生代使用的是标记复制算法，老年代使用的是标记整理算法。这样选择垃圾收集算法的原因是：老年代中一次垃圾标记后存活的对象比较多，“复制”的时候比较耗时，因此，选择了标记整理算法，还避免了内存碎片的产生。新生代与之相反，选择了标记复制算法。

    在客户端场景下使用：简单高效，在单个 CPU 环境下，避免了线程交互的开销；而且客户端内存相对较小，停顿是可以接受的

  2. 第二组：Parallel Scavenge 收集器与Parallel Old 收集器

适用于服务端场景下，追求高吞度量，且与用户的交互不多场景下使用；

吞度量与停顿时间是不可兼得的。多次gc可以实现每次gc停顿时间比较少，但是多次gc导致吞度量降低

都是多线程的

  1. 第三组：ParNew 收集器与CMS 收集器

    适用于服务端场景下，追求低延迟；

    ParNew是 Serial 收集器的多线程版本，除了性能原因外，主要是因为除了 Serial 收集器，只有它能与 CMS 收集器配合使用。

    CMS详细介绍：

    1. CMS（Concurrent Mark Sweep），使用标记 - 清除算法；以追求低停顿为目标；在整个过程中耗时最长的并发标记和并发清除过程中，收集器线程都可以与用户线程一起工作，不需要进行停顿，用户不会感到明显的卡顿。

    2. 工作流程：

      标记：

      ①初始标记：需要停顿，仅使用一条初始标记线程对所有与 GC Roots 直接关联的对象进行标记。

      ②并发标记：不需停顿，使用多条标记线程，与用户线程并行。此过程进行可达性分析，标记出所有废弃对象。速度最慢。

      ③重新标记：需要停顿，使用多条标记线程==>标记步骤②用户线程继续运作所产生的新垃圾。

      清除：

      ④并发清除：不需停顿，只使用一条 GC 线程，与用户线程并发执行，清除刚才标记的对象。这个过程非常耗时。

    3. 缺点：

      ①：低延迟导致的吞吐量低

      ②：标记清除算法导致的空间碎片：往往出现老年代空间剩余，但无法找到足够大连续空间来分配当前对象，不得不提前触发一次 Full GC。

      ③：无法处理浮动垃圾，可能出现 Concurrent Mode Failure。浮动垃圾是指并发清除阶段由于用户线程继续运行而产生的垃圾，这部分垃圾只能到下一次 GC 时才能进行回收。由于浮动垃圾的存在，因此需要预留出一部分内存，意味着 CMS 收集不能像其它收集器那样等待老年代快满的时候再回收。如果预留的内存不够存放浮动垃圾，就会出现 Concurrent Mode Failure，这时虚拟机将临时启用 Serial Old 来替代 CMS。

  2. 第四组：G1 收集器

G1 是一款面向服务端应用的垃圾收集器，它没有新生代和老年代的概念，而是将堆划分为一块块独立的 Region。当要进行垃圾收集时，首先估计每个 Region 中垃圾的数量，每次都从垃圾回收价值最大的 Region 开始回收，因此可以获得最大的回收效率。

这里抛个问题 👇
一个对象和它内部所引用的对象可能不在同一个 Region 中，那么当垃圾回收时，是否需要扫描整个堆内存才能完整地进行一次可达性分析？

并不！每个 Region 都有一个 Remembered Set，用于记录本区域中所有对象引用的对象所在的区域，进行可达性分析时，只要在 GC Roots 中再加上 Remembered Set 即可防止对整个堆内存进行遍历。

如果不计算维护 Remembered Set 的操作，G1 收集器的工作过程分为以下几个步骤：

  • 初始标记：需要停顿，仅使用一条初始标记线程对所有与 GC Roots 直接关联的对象进行标记。
  • 并发标记：不需停顿，使用一条标记线程与用户线程并发执行。此过程进行可达性分析，速度很慢。
  • 最终标记：需要停顿，使用多条标记线程并发执行。
  • 筛选回收：需要停顿，使用多条筛选回收线程并发回收废弃对象。

特点：

  • 空间整合：整体来看是基于“标记 - 整理”算法实现的收集器，从局部（两个 Region 之间）上来看是基于“复制”算法实现的，这意味着运行期间不会产生内存空间碎片。
  • 可预测的停顿：能让使用者明确指定在一个长度为 M 毫秒的时间片段内，消耗在 GC 上的时间不得超过 N 毫秒。
